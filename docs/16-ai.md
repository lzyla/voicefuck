# ETAP 16 — AI: pamięć, RAG, prompty, generatory

> Moduł `core/ai` (prompty, `ConversationEngine`, `MemoryManager`, analiza,
> `ExerciseGenerator`, embeddings) + `MemoryConsolidationWorker` (WorkManager).
> Tabela pamięci: `ai_memories` (etap 14), DTO: etap 13, transport: etap 15.

## 1. Architektura pamięci rozmów

### 1.1 Pamięć krótkoterminowa — okno kontekstu

- `ConversationEngine` buduje listę `messages` do Chat Completions z **ostatnich
  N = 30 wiadomości** bieżącej rozmowy (`MessageDao.getLastMessages(conversationId, 30)`),
  w kolejności chronologicznej, po system prompcie.
- 30 wiadomości ≈ 900–1500 tokenów — mieści się z zapasem w kontekście
  `gpt-4o-mini`, a wystarcza na spójność wątku 10–15-minutowej rozmowy.
- Wiadomości starsze niż okno nie giną (Room = źródło prawdy) — po prostu nie
  wchodzą do promptu; ich esencja wraca do modelu przez pamięć długoterminową.

### 1.2 Pamięć długoterminowa — `ai_memories`

Trwałe, skondensowane wspomnienia o uczniu, jeden fakt na rekord, po angielsku:

| `kind` | Przykład `content` |
|---|---|
| `FACT` | "Works as an Android developer, mainly with Kotlin." |
| `PREFERENCE` | "Prefers job-interview and business scenarios over small talk." |
| `WEAKNESS` | "Confuses Past Simple with Present Perfect for finished time periods." |
| `GOAL` | "Preparing for a senior developer job interview in English." |
| `PROGRESS` | "Now uses 'for/since' correctly most of the time (improved in July)." |

Pola: `importance` (0.0–1.0), `embedding` (1536-D BLOB), `createdAt`, `updatedAt`.

## 2. Pipeline konsolidacji pamięci

Po zakończeniu rozmowy (`status = COMPLETED`) planowany jest
`MemoryConsolidationWorker` (constraint: `NetworkType.CONNECTED`):

```
transkrypcja rozmowy + istniejące wspomnienia
        │ 1. Chat Completions (Memory Consolidator prompt, json_object)
        ▼
MemoryExtractionDto { memories: [ {kind, content, importance} ] }
        │ 2. deduplikacja (patrz §5.2)
        ▼
nowe / zaktualizowane AiMemory
        │ 3. POST /v1/embeddings (batch, text-embedding-3-small)
        ▼
FloatArray(1536) per wspomnienie
        │ 4. zapis: AiMemoryDao.upsert (embedding jako BLOB)
        ▼
ai_memories  ── 5. pruning gdy count() > limit (§5.3)
```

Kroki:
1. **Ekstrakcja (LLM):** do promptu wchodzi transkrypcja (tylko wypowiedzi
   USER + minimalny kontekst ASSISTANT) oraz lista istniejących wspomnień
   (id + kind + content), by model mógł wskazać aktualizacje zamiast duplikatów.
2. **Deduplikacja:** wspomnienie-kandydat z podobieństwem kosinusowym ≥ 0.90 do
   istniejącego ⇒ traktowane jako **aktualizacja** (podmiana `content`, `updatedAt = now`,
   `importance = max(stara, nowa)`), nie nowy rekord.
3. **Embedding:** batch — jedno żądanie na całą partię kandydatów.
4. **Zapis:** `upsert` w transakcji.
5. **Porażka sieci/429:** `Result.retry()` — WorkManager ponowi z backoff;
   wspomnienia bez embeddingu (`embedding IS NULL`) zostaną uzupełnione przy
   kolejnym przebiegu (dlatego kolumna jest nullable).

## 3. RAG — wstrzykiwanie pamięci do rozmowy

Przed startem rozmowy (i przy zmianie tematu) `MemoryManager` wykonuje:

1. **Zapytanie:** tekst = scenariusz + tytuł + ostatnie 1–2 wypowiedzi użytkownika
   (dla nowej rozmowy: sam scenariusz + cele z onboardingu).
2. **Embedding zapytania:** `POST /v1/embeddings` (1 krótki tekst, koszt pomijalny).
   Brak sieci ⇒ fallback: top-K po samym `importance DESC, updatedAt DESC`.
3. **Podobieństwo kosinusowe w Kotlinie** nad `getAllWithEmbedding()`:

```kotlin
fun cosineSimilarity(a: FloatArray, b: FloatArray): Float {
    var dot = 0f; var na = 0f; var nb = 0f
    for (i in a.indices) { dot += a[i] * b[i]; na += a[i] * a[i]; nb += b[i] * b[i] }
    return dot / (sqrt(na) * sqrt(nb) + 1e-10f)
}
// ranking: score = 0.75 * cosine + 0.25 * importance
```

   Przy limicie ~500 wspomnień to ≤ 500 × 1536 mnożeń — pojedyncze milisekundy
   na `Dispatchers.Default`; baza wektorowa jest zbędna.
4. **Top-K = 8** wspomnień (z progiem cosine ≥ 0.3) formatowanych do sekcji
   `Student memory` system promptu tutora (§8.1). `GOAL` i świeże `WEAKNESS`
   mają gwarantowane miejsce (po jednym najważniejszym), reszta z rankingu.

## 4. Embeddings — parametry

- Model: **`text-embedding-3-small`**, **1536 wymiarów**, wejście po angielsku
  (treści `ai_memories` są po angielsku — spójna przestrzeń wektorowa).
- Przechowywanie: `FloatArray(1536)` → **BLOB** 6144 B (konwerter little-endian,
  etap 14). 500 wspomnień ≈ 3 MB.
- Normalizacja: embeddingi OpenAI są już znormalizowane, ale liczymy pełny
  cosine (odporność na przyszłą zmianę modelu embeddingów).
- Zmiana modelu embeddingów w przyszłości ⇒ wymiary niekompatybilne ⇒ migracja:
  wyczyszczenie kolumny `embedding` i przeliczenie w tle.

## 5. Long Term Memory — cykl życia

### 5.1 Ważność (`importance`)

Nadawana przez LLM przy ekstrakcji (0.0–1.0) wg wytycznych promptu:
cele i trwałe fakty ≥ 0.7; preferencje 0.4–0.7; drobne, ulotne obserwacje ≤ 0.4.
`importance` wchodzi do rankingu RAG (waga 0.25) i decyduje o kolejności pruningu.

### 5.2 Aktualizacja vs duplikat

- cosine(kandydat, istniejące) **≥ 0.90** ⇒ aktualizacja istniejącego rekordu
  (nowy `content`, `updatedAt`, `importance = max`);
- **0.75–0.90** i ten sam `kind` ⇒ konflikt — wygrywa nowszy `content`
  (LLM widzi stare wspomnienia w prompcie i sam zwraca wersję scaloną);
- **< 0.75** ⇒ nowy rekord.
- `WEAKNESS`, która wg analizy została opanowana (np. odpowiadający `user_error`
  ma `resolvedAt`), jest przepisywana na `PROGRESS` przy kolejnej konsolidacji
  (robi to LLM — prompt §8.4 tego wymaga).

### 5.3 Zapominanie / pruning

Po każdej konsolidacji, gdy `AiMemoryDao.count() > 500`:
1. kandydaci do usunięcia: najniższy wynik `retention = importance * recencyFactor`,
   gdzie `recencyFactor = 0.5^(dni od updatedAt / 90)` (półtrwanie 90 dni);
2. `GOAL` nigdy nie jest usuwany automatycznie (usuwa go tylko zmiana celów
   w ustawieniach lub przepisanie na `PROGRESS`);
3. usuwamy nadwyżkę ponad limit (`deleteByIds`).
Użytkownik może przejrzeć i skasować wspomnienia w `SettingsDataScreen` (prywatność).

## 6. Generatory i analizy

### 6.1 Generowanie ćwiczeń (z `user_errors`)

Wejście: `UserErrorDao.getUnresolved(limit = 10)` (najświeższe nierozwiązane
błędy) + poziom ucznia. Prompt §8.3 → `GeneratedExercisesDto` → mapowanie na
`Exercise` (etap 13): `dueAt = now`, SM-2 od zera (`easeFactor 2.5`,
`intervalDays 0`, `repetitionCount 0`). Typy: `FILL_GAP`, `MULTIPLE_CHOICE`
(3–4 `options`), `TRANSLATION` (PL→EN), `SPEAKING` (zdanie do powiedzenia,
oceniane przez STT jak wymowa). Walidacja przed zapisem: `correctAnswer` musi
występować w `options` dla MULTIPLE_CHOICE; nieznany `type` ⇒ odrzucenie pozycji.

### 6.2 Analiza błędów po rozmowie

Po `status = COMPLETED`: transkrypcja + poziom → prompt §8.2 (json_object) →
`ConversationAnalysisDto`. Zapis w jednej transakcji:
`summary` → `conversations.summary` (+ `status = ANALYZED`), `errors` →
`user_errors`, `vocabulary` → `vocabulary_items` (dedup po `word` — UNIQUE;
istniejące słówko nie jest nadpisywane), `overall_feedback` → ekran
`ConversationSummaryScreen`. Limity: max 10 błędów, max 8 słówek na rozmowę
(egzekwowane promptem i defensywnie `take(n)` w kodzie).

### 6.3 Analiza wymowy (hybrydowa)

Trening słowa/zdania w `PronunciationScreen`:

1. **STT:** użytkownik czyta `expectedText`; `SpeechRecognizerManager` zwraca
   `recognizedText` + `confidence` (0.0–1.0, bywa niedostępny).
2. **Porównanie tekstów w Kotlinie:** znormalizowane (lowercase, bez interpunkcji)
   podobieństwo Levenshteina na słowach:
   `textScore = 1 - editDistance(expectedWords, recognizedWords) / max(len)`.
3. **Score 0–100:**
   `score = round(100 * (0.6 * textScore + 0.4 * confidence))`;
   gdy confidence niedostępny: `score = round(100 * textScore)`.
4. **Feedback LLM** (prompt §8.5): expected vs recognized + score → 2–3 zdania
   wskazówek po polsku (które słowo brzmiało jak co, jak ułożyć usta/akcent).
   Offline ⇒ feedback szablonowy z samego porównania tekstów.
5. Zapis do `pronunciation_results`; wynik < 60 może dodać `user_error`
   kategorii `PRONUNCIATION`.

### 6.4 Tygodniowy raport

Raz w tygodniu (WorkManager, niedziela wieczór) lub na żądanie ze
`StatisticsScreen`: agregaty z `daily_stats` (7 dni + poprzedni tydzień dla
porównania), top kategorie z `user_errors`, nowe/opanowane słówka, średnia wymowy
→ Chat Completions (bez json_object, markdown po polsku) → zapis + notyfikacja.
Prompt: rola "encouraging coach", struktura: nagłówek, 3 sukcesy, 2 obszary do
pracy, konkretny plan na kolejny tydzień. Brak danych (0 rozmów) ⇒ raport
motywacyjny bez statystyk.

## 7. Personalizacja

- **Poziom ucznia** (`UserPreferences.englishLevel`, A2–C1) steruje promptem tutora:
  - **A2:** proste słownictwo (top 1500 słów), krótkie zdania (≤ 12 słów),
    wolniejsze TTS (0.85), częstsze parafrazy, jedna myśl na wypowiedź;
  - **B1:** codzienne słownictwo + podstawowe idiomy, zdania złożone współrzędnie,
    TTS 0.95;
  - **B2:** naturalne tempo (1.0), idiomy i phrasal verbs, pytania otwarte,
    dłuższe wypowiedzi;
  - **C1:** pełna naturalność, niuanse rejestru (formal/informal), słownictwo
    specjalistyczne, korekta subtelności.
- **Cele z onboardingu** (`learningGoals` + `dailyGoalMinutes`) wchodzą do
  system promptu (sekcja Student profile) i sterują doborem scenariuszy
  proponowanych na Home.
- **Pamięć długoterminowa** (top-K z RAG) domyka personalizację: tutor odnosi
  się do pracy, planów i słabości ucznia oraz celowo wywołuje struktury,
  z którymi uczeń ma problem (`WEAKNESS`).
- Trudność ćwiczeń i feedbacku analizy również parametryzowana poziomem
  (te same wartości wstawiane do promptów §8.2–8.3).

## 8. System prompty (pełne treści, EN)

Prompty trzymane w `core/ai/prompts/` jako stałe z placeholderami `{{...}}`
wypełnianymi przez builder.

### 8.1 Tutor konwersacji (Conversation Tutor)

```
You are Coach, a friendly and patient English conversation tutor inside the
"AI English Coach" Android app. Your student is a Polish adult learning spoken
English. Your job is to hold a natural, engaging VOICE conversation that the
student hears via text-to-speech.

STUDENT PROFILE
- CEFR level: {{LEVEL}} (A2 | B1 | B2 | C1)
- Learning goals: {{GOALS}}
- Current scenario: {{SCENARIO}} ({{SCENARIO_DESCRIPTION}})

STUDENT MEMORY (long-term facts about this student — use them naturally, do not
recite them):
{{MEMORIES}}

CONVERSATION RULES
1. Speak ONLY English. Never switch to Polish, even if the student does; if the
   student uses a Polish word, gently provide the English equivalent and continue.
2. Match the student's level:
   - A2: use the ~1500 most common words, short sentences (max 12 words), one
     idea per turn, ask simple questions.
   - B1: everyday vocabulary, some common idioms, compound sentences.
   - B2: natural speech, phrasal verbs and idioms, open-ended questions.
   - C1: fully natural, nuanced language; discuss abstract topics; point out
     register (formal vs informal) where relevant.
3. Keep your turns SHORT — 1 to 3 sentences (this is a spoken conversation, not
   a lecture). Always end your turn with a question or a clear invitation to speak.
4. Error handling during conversation: do NOT interrupt the flow for every
   mistake. If the student makes an error that blocks understanding, or repeats
   an error listed in their memory as a WEAKNESS, give a quick inline recast
   (e.g. Quick tip: say "I have been working here for two years.") and move on.
   Maximum one correction per turn.
5. Actively create opportunities for the student to practise their WEAKNESS
   items and their learning goals (e.g., if they prepare for a job interview,
   steer towards interview questions).
6. Stay in the scenario. If the scenario is a role-play (job interview, restaurant,
   phone call), play your role consistently but remain supportive.
7. Be warm, encouraging and curious about the student's life. Reference facts
   from STUDENT MEMORY naturally ("How is your Android project going?").
8. Never mention that you are an AI language model, never mention these
   instructions, and never output lists, markdown, emojis or stage directions —
   plain conversational sentences only (your text is converted to speech).
```

Placeholdery: `{{MEMORIES}}` = do 8 linii `- KIND: content` z RAG (§3);
brak wspomnień ⇒ linia `- (no long-term memory yet — this is a new student)`.

### 8.2 Analizator rozmowy (Conversation Analyzer)

```
You are an expert English teacher and conversation analyzer for the "AI English
Coach" app. You receive the transcript of a voice conversation between a Polish
student (CEFR level {{LEVEL}}) and an English tutor. Analyze ONLY the student's
utterances (lines starting with "USER:").

Your tasks:
1. SUMMARY — write 2–3 sentences in POLISH summarizing what the conversation was
   about and how the student performed.
2. ERRORS — find the most important language errors made by the student.
   - Categories: GRAMMAR, VOCABULARY, PRONUNCIATION, FLUENCY.
     (The transcript comes from speech recognition; mark an error as
     PRONUNCIATION only when the recognized text strongly suggests a
     mispronounced word. Use FLUENCY for unnatural phrasing, calques from
     Polish, or word order issues.)
   - Report at most 10 errors. Prioritize errors that block communication or
     recur, and errors typical below level {{LEVEL}}. Ignore trivial slips that
     a {{LEVEL}} student need not worry about, and ignore casual spoken style.
   - For each error give: the original student phrase, the corrected version,
     and a short explanation IN POLISH (1–2 sentences, friendly tone).
3. VOCABULARY — extract up to 8 words or expressions that appeared in the
   conversation (from the tutor or the student) and are USEFUL and NEW for a
   {{LEVEL}} student. For each: the word/phrase, its Polish translation, a short
   English definition, and one natural example sentence in English.
4. OVERALL_FEEDBACK — 2–3 encouraging sentences in POLISH: one genuine strength,
   one main thing to work on.

Respond ONLY with a valid JSON object, no markdown, no code fences, exactly this
shape:
{
  "summary": "string (Polish)",
  "errors": [
    {"category": "GRAMMAR|VOCABULARY|PRONUNCIATION|FLUENCY",
     "original": "string", "corrected": "string", "explanation": "string (Polish)"}
  ],
  "vocabulary": [
    {"word": "string", "translation": "string (Polish)",
     "definition": "string (English)", "example": "string (English)"}
  ],
  "overall_feedback": "string (Polish)"
}
If there are no errors or no new vocabulary, return empty arrays.
```

### 8.3 Generator ćwiczeń (Exercise Generator)

```
You are an English exercise generator for the "AI English Coach" app. You
receive a list of real errors made by a Polish student (CEFR level {{LEVEL}}),
each with an id, category, the original incorrect phrase and the corrected
version.

Generate {{COUNT}} practice exercises that directly target these errors.

Exercise types (use a mix; pick the type that best fits each error):
- FILL_GAP: a sentence with one gap written as "___"; put the missing word(s)
  in correct_answer. You may include a hint in brackets, e.g. "___ (go)".
- MULTIPLE_CHOICE: a question plus 3–4 options; exactly one is correct and it
  must be copied verbatim into correct_answer. Distractors must reflect the
  student's actual mistake pattern.
- TRANSLATION: a short Polish sentence in question; correct_answer is its
  natural English translation practising the target structure.
- SPEAKING: question is an instruction plus an English sentence the student must
  say aloud; correct_answer is that exact sentence.

Rules:
1. Every exercise must clearly practise the structure from one source error and
   must include that error's id in source_error_id.
2. Difficulty must match level {{LEVEL}} — same grammar point, but vocabulary
   the student already knows.
3. Do NOT reuse the student's original sentence verbatim — create a fresh,
   natural context.
4. explanation: 1–2 sentences IN POLISH explaining the rule being practised.
5. For FILL_GAP, TRANSLATION and SPEAKING, options must be an empty array.

Respond ONLY with a valid JSON object, no markdown, exactly this shape:
{
  "exercises": [
    {"type": "FILL_GAP|MULTIPLE_CHOICE|TRANSLATION|SPEAKING",
     "question": "string", "options": ["string"],
     "correct_answer": "string", "explanation": "string (Polish)",
     "source_error_id": "string"}
  ]
}
```

### 8.4 Konsolidator pamięci (Memory Consolidator)

```
You are the long-term memory module of the "AI English Coach" app. You receive:
(1) the transcript of a finished conversation between a Polish student and their
English tutor, and (2) the list of memories already stored about this student.

Extract NEW long-term knowledge about the student worth remembering for future
conversations. Kinds:
- FACT: stable facts about their life (job, family, city, hobbies, projects).
- PREFERENCE: how they like to learn or talk (topics, scenarios, correction style).
- WEAKNESS: recurring language problems (specific grammar points, vocabulary
  gaps, pronunciation issues).
- GOAL: why they are learning English and any deadlines.
- PROGRESS: concrete improvements ("now uses X correctly", milestones reached).

Rules:
1. Each memory is ONE self-contained English sentence (max 20 words), written in
   third person, understandable without the transcript.
2. Do NOT duplicate an existing memory. If the conversation UPDATES an existing
   memory (new job, goal achieved, weakness overcome), return the updated
   sentence — it will replace the old one. If an existing WEAKNESS is now
   clearly mastered, return it as PROGRESS instead.
3. Only include things that will matter in conversations weeks from now. Skip
   small talk details, one-off topics and anything about the tutor.
4. importance (0.0–1.0): goals and stable life facts 0.7–1.0; preferences and
   typical weaknesses 0.4–0.7; minor observations 0.1–0.4.
5. Return at most 6 memories. Returning an empty list is a perfectly good answer
   when nothing new was revealed.

Respond ONLY with a valid JSON object, no markdown, exactly this shape:
{
  "memories": [
    {"kind": "FACT|PREFERENCE|WEAKNESS|GOAL|PROGRESS",
     "content": "string (English, one sentence)", "importance": 0.0}
  ]
}
```

### 8.5 Feedback wymowy (Pronunciation Feedback)

```
You are a pronunciation coach for Polish learners of English in the "AI English
Coach" app. The student (CEFR level {{LEVEL}}) tried to say a target phrase; a
speech recognizer transcribed what it heard.

You receive:
- expected: the target phrase
- recognized: what the speech recognizer heard
- score: an automatic pronunciation score 0–100

Write feedback IN POLISH, 2–3 short sentences, for a mobile screen:
1. Start with one positive note (what was recognized correctly).
2. Point out the specific word(s) that were misheard and explain the likely
   pronunciation problem, considering typical Polish-speaker issues (th → f/d/z,
   short vs long vowels as in ship/sheep, final devoicing as in "dog" → "dok",
   silent letters, word stress). Show the problem word with a simple phonetic
   hint, e.g. "three" ≈ "θriː" (język między zębami).
3. Give one concrete tip how to practise it.

If score >= 85, congratulate briefly and suggest a harder aspect to polish
(intonation, linking). Never shame the student. Respond with plain text only —
no JSON, no markdown, no English sentences except the practised words themselves.
```

## 10. Degradacja — co gdy AI niedostępne

Zasada: **aplikacja bez sieci pozostaje w pełni użyteczna do nauki z danych
lokalnych**; niedostępne są tylko nowe treści od AI.

| Funkcja | Zachowanie offline / przy `AiError` |
|---|---|
| Rozmowa z tutorem | niedostępna — `ErrorBanner` z przyczyną (`Network`/`InvalidApiKey`/`RateLimited`) i CTA (ustawienia / ponów); zachęta do trybów offline |
| Analiza rozmowy | rozmowa zapisana ze `status = COMPLETED`; analiza kolejkowana (worker z constraint sieci) — dogania po odzyskaniu sieci |
| Konsolidacja pamięci | `Result.retry()` w workerze; wspomnienia bez embeddingu uzupełniane później |
| RAG przy starcie rozmowy | fallback bez embeddingu zapytania: top-K po `importance` + świeżości (§3 pkt 2) |
| Ćwiczenia, fiszki SRS | w pełni offline (dane w Room); brak tylko generowania nowych |
| Analiza wymowy | STT on-device często działa; score liczony lokalnie (§6.3), feedback szablonowy zamiast LLM |
| Notatki głosowe | nagrywanie offline; transkrypcja gdy STT wymaga sieci — kolejkowana |
| Statystyki, historia, słownictwo | w pełni offline |
| Raport tygodniowy | odroczony do dostępności sieci |

Komunikaty rozróżniają przyczyny: `InvalidApiKey` ⇒ "Sprawdź klucz API w
ustawieniach"; `RateLimited` ⇒ "Limit zapytań — spróbuj za chwilę";
`Network` ⇒ "Brak internetu — możesz ćwiczyć powtórki offline". Żadna operacja
AI nie blokuje zapisu danych lokalnych (Room najpierw, AI potem — brief, rozdz. 4).
